# 0003 - Delegates become tool-using sub-agents (no git_commit)
status: accepted
tags: delegate, tools, subagent, approval, architecture
summary: Delegates get a real tool-using ReAct/native sub-agent loop with auto-approval after a gated handoff, denied only git_commit/session/delegate/ask tools

## Context
DelegateTool (crates/comrade-core/src/delegate.rs) ran a single non-streaming client.chat with NO tools — the delegate returned text the root then applied. Users want real delegation: the delegate itself reads/writes/searches/remembers in the repo and only cannot git_commit. Decided with the user: (1) delegate tool call is approval-gated once by the human (add `delegate` to MUTATING_TOOLS + APPROVAL_GATED_TOOLS in agent.rs); (2) once approved, all nested tool calls auto-run (delegate ctx is a clone of the parent ctx with auto_approve=true); (3) denied tools by name: git_commit, delegate (no recursion), ask_question, rename_session, set_status_bar, set_plan, update_plan, finish_plan — everything else from the main registry stays; (4) parallel delegate batches stay parallel (user accepted file-conflict risk); (5) delegates self-verify with run_tests/run_task and still close with a VERIFICATION: line; the root re-verifies. Plan-step enforcement (mark_step_delegated, fix rounds, working:<model> note) is untouched and must stay intact.

## Decision
1. main.rs build_tools (crates/comrade-tui/src/main.rs): build a SECOND ToolRegistry `delegate_tools` from the same crate all() lists, skipping tools whose spec().name is in a deny list (git_commit, delegate, ask_question, rename_session, set_status_bar, set_plan, update_plan, finish_plan). Pass it into DelegateTool::new(&cfg.delegates, delegate_tools, limits) where limits = {max_iterations, budget_tokens, max_tool_output_chars} copied from cfg. Put the deny list as pub const in delegate.rs so main.rs and tests share it.
2. delegate.rs invoke: after existing validation + fix-round bookkeeping, run a tool-using sub-loop instead of client.chat: delegate system prompt (role + tools + you cannot git_commit + auto-approval granted + reply with final summary and VERIFICATION: line), ctx2 = ctx.clone() with auto_approve=true and fresh approval mutex, ContextManager::with_system + push user messages, loop chat_turn dispatching tool calls into delegate_tools with ctx2, appending render_observation results; stop when a turn has no tool call -> content is the reply. On error restore step status; keep mark_step_delegated on success.
3. agent.rs: add "delegate" to MUTATING_TOOLS and APPROVAL_GATED_TOOLS so the human approves the handoff once in Ask mode. The agent loop already calls ctx.set_approval for gated tools before invoke in both ReAct and native paths.
4. No extra ctx.confirm inside DelegateTool::invoke: nested calls use ctx2 with auto_approve=true.
5. Tests in delegate.rs: fake servers must become SSE chat_turn-compatible (copy agent.rs streaming fake) because client.chat is no longer used; keep existing assertions on prompt content / fix rounds; add a test where the fake server first emits a native tool_call (e.g. write_file) then a final answer to prove the delegate executed a real tool; unit-test the deny list contains git_commit but not write_file/run_tests/remember.
6. Prompt text updates: SUBAGENT_SYSTEM in delegate.rs, react.rs delegation paragraphs, delegate tool description must stop claiming "no tools".

## Consequences
Delegates now cost more tokens/turns (real loop) and can mutate files concurrently in parallel batches — accepted. Undo/MemoryUndo is Mutex-backed so captures are safe. Existing delegate tests rely on request_spy single-shot content: they need rework to SSE + multi-turn. git read-only tools kept for delegates; only git_commit is denied. session tools denied so a delegate cannot corrupt the root's plan (plan step enforcement depends on it).
