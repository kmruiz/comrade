# 0024 - Stuck-run freeze: delegate sub-agent was uncancellable (Esc dead at "working")
status: accepted
tags: delegate, agent, bugfix, cancellation, stall, toolcontext, stuck
summary: User: agent/delegate "blocked, does nothing" at working; whole app seemed frozen, Esc couldn't quit. Root cause: delegate sub-loop never watched the run's CancellationToken, so a delegate whose LLM request stalled held the whole run hostage; root only raced stop around its own chat_turn.

## Context
Comrade runs the model on a background task (tui.rs run select loop, 100ms spin tick) so the TUI is not structurally blocked by a slow model; a "frozen / can't cancel" complaint therefore means the run task is stuck in an await that ignores the cancel token. agent.rs run_agent_loop races its own client.chat_turn against stop (tokio::select! ~line 481) and checks stop at the top of the loop, but tool.invoke (both ReAct path and run_native_calls) is awaited with NO stop race. run_delegate_subagent (delegate.rs) called client.chat_turn_once with no token at all: a stalled delegate request ignored Esc until the delegate client's own timeout_secs (default 600!) fired. Root LLM requests share that 600s ceiling, which is also why plain stalls look like "does nothing" for ages. Delegates are invoked via a ToolRegistry shared across runs, so the token cannot live on DelegateTool; it was threaded through ToolContext instead.

## Decision
1. Add `pub stop: Option<CancellationToken>` to comrade-tool ToolContext (crates/comrade-tool/src/tool.rs) + `tokio-util.workspace = true` to comrade-tool/Cargo.toml. 2. agent.rs run_agent_loop sets `ctx.stop = Some(stop.clone())` right where it sets ctx.events (per-run wiring pattern). 3. delegate.rs run_delegate_subagent clones parent_ctx.stop; bails at the top of each iteration when cancelled, and races `chat_turn_once` in tokio::select! against `stop.cancelled()` (mirror of agent.rs) so an in-flight delegate request aborts on cancel. 4. When the delegate bails, invoke returns Err -> root renders it as an ERROR tool result -> next loop iteration's top-of-loop stop check bails the run with "agent interrupted by user" -> TUI RunEnd, control restored. 5. Test: cancelled_run_aborts_a_delegate_stuck_waiting_for_the_model (silent TCP server + cancel 300ms in; asserts Err contains "interrupted" and elapsed < 2s; delegate client timeout_secs overridden to 5 so a regression fails in seconds).

## Consequences
All ToolContext literal sites (~15 across comrade-tool/comrade-core/*-fs/-session/comrade-tui) needed `stop: None`. Runs are serialized so one token per run is safe; headless runs also pass a stop token so delegates there are cancellable too. The whole-app-freeze symptom may also involve a stuck ROOT LLM request where the user never pressed Esc: those are still bounded only by llm.timeout_secs (default 600) - revisit if a stall reproduces with no cancel. If "frozen" recurs, capture where it's stuck (gdb -p <pid> -batch -ex 'thread apply all bt') before killing.
