# 0041 - System prompts extracted to markdown assets (include_str!)
status: accepted
date: 2026-09-09
tags: prompt, react, delegate, include_str, markdown, comrade-core, tooling
summary: The root and delegate system-prompt prose moved out of Rust string literals into per-section .md files under crates/comrade-core/prompts/, embedded at compile time via include_str! constants

## Context
The system prompts built in crates/comrade-core/src/react.rs (build_system_prompt) and crates/comrade-core/src/delegate.rs (delegate_system_prompt) were long, prose-heavy Rust string literals with `\` line continuations and `\n` escapes — hard to read, diff, and edit. The user asked to extract the prompts to markdown files and import them at compile time with include_str!.

## Decision
1. New directory `crates/comrade-core/prompts/` holds one markdown file per prompt section: intro.md, delegate-by-default.md, working-style.md, delegation-lead.md, memory.md, trust-boundaries.md, tools-intro.md, protocol.md (the root prompt) and delegate-system.md (the delegate sub-agent body). Content was generated by DECODING the existing Rust literals (a throwaway Python script), so the rendered output is byte-identical — no transcription drift.
2. react.rs declares `const INTRO/DELEGATE_BY_DEFAULT/WORKING_STYLE/DELEGATION_LEAD/MEMORY/TRUST_BOUNDARIES/TOOLS_INTRO/PROTOCOL: &str = include_str!("../prompts/<file>.md");` and build_system_prompt simply pushes the constants in the previous order around the dynamic parts (Working directory, Context budget, and the delegate-gated DELEGATE_BY_DEFAULT/DELEGATION_LEAD sections and the per-tool render loop).
3. delegate.rs keeps building the tool lines and the native-vs-ReAct protocol snippet in Rust; the static body is include_str!("../prompts/delegate-system.md") with {project_root}/{tool_lines}/{protocol} placeholders substituted at runtime — {tool_lines} and {protocol} are replaced before {project_root} so tool descriptions containing braces cannot disturb later substitutions.
4. Regression tests: react.rs dev_prompt_tests::prompt_sections_are_loaded_from_markdown_in_order (head/tail/order of the assembled sections, tools intro precedes first rendered tool line) and delegate.rs tests::delegate_system_prompt_substitutes_tokens_from_markdown (no placeholder left, working directory and tool lines present, both native and ReAct).

## Rationale
Markdown is the natural editing format for long agent-facing prose: no escaping, visible headings/paragraphs, clean diffs, and editors render it. include_str! embeds at compile time so there is no runtime file dependency or path resolution — the binary stays self-contained and a missing file is a compile error.

## Alternatives considered
- A single system.md template with {{placeholder}} tokens .replace()d for all dynamic parts: rejected — the delegate-conditional sections and the per-tool loop make one template awkward; per-section constants keep the assembly logic in Rust and each section independently editable.
- Keeping delegate.rs prose inline while only extracting the root prompt: rejected — consistency; both prompts are edited by the same people.
- Loading the files at runtime: rejected — include_str! was requested and gives compile-time guarantees.

## Scope
In: comrade-core/src/react.rs, comrade-core/src/delegate.rs, crates/comrade-core/prompts/*.md, plus the two regression tests. Out: rendered prompt content is unchanged (byte-identical), no config/TUI changes.

## Impact
- Editing agent prompts now means editing markdown files under crates/comrade-core/prompts/; rustfmt never touches them and diffs are readable.
- A future prompt change no longer requires careful `\`-continuation editing inside Rust strings.
- Adding/removing a section means adding/removing a const + .md file and updating the assembly.
- The prompts directory is part of the crate and shipped with it; there is no runtime file lookup.
