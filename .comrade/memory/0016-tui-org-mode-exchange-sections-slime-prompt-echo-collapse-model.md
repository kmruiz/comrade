# 0016 - TUI org-mode exchange sections: SLIME prompt echo + collapse model
status: accepted
tags: comrade-tui, tui, chat-layout, org-mode, sections, emacs
summary: comrade-tui chat transcript: each user turn is an org-style section (heading = "> " prompt echo, body = the exchange); Tab/click folds/unfolds; Ctrl-P/N skip hidden rows; Ctrl-S auto-expands

## Context
User asked for a SLIME+org-mode chat window (emacs-y): input at the bottom as "> ", scroll up the transcript, toggle whole exchanges. Implemented in crates/comrade-tui/src/tui.rs. Prior work (run books #10/#11/#12/#13) had already: bottom prompt above an emacs mode line, run-digest folding, M-x palette, Ctrl-S search. This change layered a per-exchange section model on top of the flat chat architecture.

## Decision
1. Section = one exchange: contiguous chat from a MsgKind::User up to (not incl.) the next User. Section ordinal = rank of its User msg among all User msgs. Ordinals are STABLE because User msgs are only appended: run-digest folds (fold_completed_runs/unfold_run) splice only Tool/Reasoning/Failure/Meta kinds, never User. Collapse state lives in `App.section_collapsed: Vec<bool>` indexed by ordinal (auto-grows; layout treats missing as expanded).
2. Pure layer (testable without an App): section_count(chat), section_of_msg(chat,idx)->(ord,user_idx) (None for pre-first-user preamble), section_collapsible(running,ord,count), collapsed_at/set_collapsed_at, expand_section, toggle_section(collapsed,chat,running,msg_idx), chat_visible(chat,collapsed,idx), step_visible(chat,collapsed,sel,dir). App methods toggle_tool (User arm) / expand_section_at wrap them.
3. Rendering: layout_messages is now a wrapper over pure `layout_chat_rows(chat,collapsed,stream,width)` (tui.rs ~2972). User turns render as a SLIME echo heading — "> " green prefix on the first wrapped row (text wrapped at width-2), "  " indented continuation rows, banded (kind==User filter in draw_chat unchanged). A collapsed section emits only its echo rows plus one dim marker row "··· N more · tab/click to expand" (only when interior msgs exist). Hidden interior msgs keep a zero-length (start,0) entry in msg_ranges so all flat indices stay valid; `_ if hiding` match arm in the layout loop does the skipping. The old author_header("you")+banded-body block is gone.
4. Keys/behaviour: Tab (and mouse click, via tool_header=Some(user_idx) on echo+marker rows) calls toggle_tool -> toggle_section. The live LAST section cannot be collapsed while app.running (section_collapsible). Ctrl-P/N move_block now uses step_visible so navigation skips hidden interiors instead of walking invisible messages. Ctrl-S goto_search_match calls expand_section_at(idx) before jumping so matches inside collapsed sections become visible.
5. Prompt polish: draw_prompt fills the bar with a green-tinted band prompt_bg() (PROMPT_BG_TINT/PROMPT_BG_ALPHA consts next to user_band_bg), pads the band flush to the right edge, keeps the "> " green+bold on the first row and dims (DarkGray fg) wrapped continuation rows; selection spans keep their own inverse shading.
VERIFY: cargo test -p comrade-tui (75 tests; section_tests + visible-block-nav tests cover helpers/layout/toggle/search-expand). cargo build -p comrade-tui clean, no new warnings. clippy --no-deps shows only pre-existing warnings (headless.rs collapsible_if, toggle_tool match_like_matches_macro etc., none from this change).

## Consequences
Known trade-offs: (a) a collapsed section still shows the FULL user echo text (heading == input echo; body = the exchange below), so pasting a huge blob keeps the heading large — folding only hides the assistant/tool content. If a truncated "first line only" heading is wanted later, the User msg needs a separate body. (b) Ctrl-S jump to a match expands its whole section. (c) No global overview toggle yet (org Shift-Tab "collapse all but live / expand all") — candidate next step as MxCommand + BackTab binding; add to MxCommand::ALL if bound (rule from #12). (d) per-child keyboard drill inside an open digest is still the open RowTarget question from #11. (e) Re-verify visually in a real terminal: tint strengths (PROMPT_BG_ALPHA, USER_BG_ALPHA) assume the DIFF_BASE_BG dark theme.
