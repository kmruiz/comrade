# 0037 - ToolRegistry live disabled filter + list-mcp-servers tool manager modal
status: accepted
tags: comrade-tui, mcp, tool-registry, tui.rs, tool-toggle
summary: M-x list-mcp-servers modal now toggles MCP tools on/off live via a new ToolRegistry disabled-name filter; resets on restart/reload

## Context
User asked for a feature on the list-mcp-servers modal (crates/comrade-tui/src/tui.rs, decision #35): enable/disable MCP server tools, filter by tool and mcp name with one text field, tool list grouped by mcp and collapsible. Chosen semantics (user-approved): in-memory for the session, applied live to the next model iteration.

## Decision
1. comrade-tool::ToolRegistry now carries `disabled: Arc<RwLock<HashSet<String>>>` (empty default). get(name) returns None for disabled tools; iter() snapshots the set once and yields only enabled; iter_all() yields everything; is_enabled/set_enabled/toggle mutate; disabled_handle() clones the Arc for UIs. Action: nothing else needed — when the set is empty behaviour is identical, so comrade-core and the delegate sub-registry are untouched. Verification: `cargo test -p comrade-tool` green (registry_tests module at end of crates/comrade-tool/src/tool.rs).
2. comrade-tool-mcp::mcp_server_prefix(server) = "mcp_<sanitised>_" was added and exported (lib.rs) so the UI can group a server's registered tools; mcp_tool_name(server, tool).starts_with(prefix). Verification: `cargo test -p comrade-tool-mcp` green.
3. The modal (McpServersView in tui.rs) now stores groups: Vec<McpToolGroup{server, tools: Vec<McpToolEntry{name,desc}>}> built from cfg.mcp.servers in config order via mcp_tool_groups() using iter_all() (so disabled tools stay visible to re-enable), plus `disabled: Arc<RwLock<HashSet<String>>>`, filter/filtering, collapsed: HashSet<usize>, sel. Pure row model: mcp_visible_rows(view) -> Vec<RowRef::{Header(gi),Tool(gi,ti)}> honours filter (server match shows the whole group; tool match shows matching rows) and collapsed (header only); mcp_clamp keeps sel valid. Unit tests mcp_tool_groups_assigns_tools_by_server_prefix + mcp_visible_rows_orders_and_filters live in tui.rs mod tests.
4. Keys in handle_mcp_key: Esc/q/ctrl-g close; Up/Down/PgUp/PgDn/ctrl-p/ctrl-n move sel over visible rows; Enter or space activates — on a tool row flips it in the shared disabled set, on a header toggles collapse; Tab toggles collapse of the group under the cursor; Left/Right collapse/expand it; '/' or 'f' enters the filter (Esc leaves it; typed chars filter live). Scroll is derived from sel at draw time (no stored scroll). Draw (draw_mcp_servers, title " MCP tools ") shows a filter line on top, rows "-/+ name · k/n on" (headers, bold) and "[x]/[ ] mcp_<server>_<tool> · desc" (tools), hint bar at the bottom. Verification: `cargo test -p comrade-tui` green, commit 1b017e8.

## Consequences
Semantics: in-memory only — toggles reset on restart AND on Ctrl-R reload-config (reload_config rebuilds a fresh ToolRegistry with an empty disabled set). Toggles reach a live agent on its NEXT iteration because agent.rs re-advertises tool specs from registry.iter() every iteration, while the session's system prompt (built once at new_session via build_system_prompt, also iter()) stays stale textually; a disabled tool invoked anyway is refused by get(). Servers are grouped by their sanitised mcp name prefix, so two configured servers whose names sanitise identically (e.g. "a-b" vs "a b") would collide into one group. The delegate sub-agent registry is built from scratch in comrade-tui main.rs delegate_registry() and is never filtered, so disabling an MCP tool does not affect delegates. Bonsai delegate model aborted twice on no-progress rgrep loops when given this task; it had started corrupting tool.rs — git-restore the file and do the work directly if that recurs.
