# 0023 - Delegate tool activity streams to the chat via ToolContext.events sink
status: accepted
tags: delegate, tui, chat, events, activity-events
summary: Delegate sub-agent tool calls/results now stream into the chat live, authored by the delegate's name, via a new ToolContext ActivityEvents sink wired to the session AgentEvent channel (DelegateToolCall/DelegateToolResult).

## Context
User reported delegate sub-agent actions were invisible in the TUI chat: only the parent's `delegate` hand-off card and the delegate's final text reply appeared. The delegate sub-agent loop (run_delegate_subagent in crates/comrade-core/src/delegate.rs) invokes tools directly and emitted no AgentEvents, while the UI only ever saw events from the main agent loop (agent.rs run_agent_loop). Fix streams each delegate tool call/result into the session event channel as it happens, tagged with the delegate's configured name.

## Decision
1. comrade-tool (tool.rs): add `#[async_trait] pub trait ActivityEvents { async fn tool_call(&self, author: &str, name: &str, args: &str); async fn tool_result(&self, author: &str, name: &str, output: &str, ok: bool); }` plus a discarding `NoopEvents`, and a new `ToolContext.events: Arc<dyn ActivityEvents>` field (every ToolContext literal now sets `events: Arc::new(comrade_tool::NoopEvents)`). 2. comrade-core/session.rs: new AgentEvent variants `DelegateToolCall { model, name, args }` and `DelegateToolResult { model, name, output, ok }`, plus `SessionEvents(pub mpsc::Sender<AgentEvent>)` implementing ActivityEvents by sending those variants. 3. comrade-core/agent.rs run_agent_loop: at entry `ctx.events = Arc::new(crate::session::SessionEvents(tx.clone()))` so every run's context (and thus the delegate dctx clone) can emit. 4. delegate.rs: `run_delegate_subagent` takes an `author: &str` (the delegate cfg.name) and wraps each real tool.invoke in BOTH dispatch paths (native + react) with `dctx.events.tool_call(...).await` / `tool_result(...).await`; refused/unknown-tool calls emit nothing. 5. comrade-tui/tui.rs: handle the two new events in the agent-event match - DelegateToolCall pushes a Tool card with `author: Some(model)`; DelegateToolResult attaches result/ok via new `last_delegate_tool_mut(name, model)` (name+author match) and `stamp_delegate_taken`; run_tests outputs get the rich summary/failure treatment like the parent path. 6. layout_run author pick now skips tool children named "delegate" so a folded delegation digest is credited to the delegate model, not the parent's hand-off card.

## Consequences
Tests: delegate_tool_activity_streams_as_chat_events (comrade-core) asserts call+result events tagged with the delegate name; run_digest_credits_the_delegate_not_the_handoff (comrade-tui) asserts the digest shows the delegate, not the hand-off author. Full `cargo test --workspace` is green. Caveats: parallel delegates sharing a tool name still match by (name, model); a delegate run_tests failure pushes author-less Failure rows (same as parent). Note the repo is NOT clippy-clean on rustc 1.97 (many pre-existing warn/deny lints in untouched crates; `cargo clippy -p comrade-tui --bins --no-deps` is the clean signal) - do not treat a noisy `cargo clippy --workspace` as a regression gate.
