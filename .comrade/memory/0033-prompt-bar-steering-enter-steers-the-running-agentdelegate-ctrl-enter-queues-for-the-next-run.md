# 0033 - Prompt-bar steering: ENTER steers the running agent/delegate, ctrl-ENTER queues for the next run
status: accepted
tags: steer, delegate, tui, agent, queue, ToolContext
summary: Steering: ENTER while a run is live injects the prompt into the running agent/delegate at its next rest point (shared Steer bus on ToolContext); ctrl-ENTER queues it for the next run; M-x 'steer' and 'queue-prompt' added.

## Context
Feature: while an agent or delegate runs, typing + ENTER steers whoever owns the loop; ctrl-ENTER queues the prompt for the next run; M-x 'steer' / 'queue-prompt' do the same. User explicitly chose: queue = deliver to next run (current run never sees it), auto-submitted at RunEnd (restored to the bar if the run was cancelled).

## Decision
1. comrade-tool tool.rs: new pub `Steer` (cloneable; shared `Arc<Mutex<UnboundedReceiver<String>>>` + `drain()`) and `ToolContext.steer: Option<Steer>`. One pipe per run; root agent loop and the nested delegate sub-loop drain the SAME bus, so whichever model currently owns the loop receives the steer. 2. comrade-core agent.rs: `pub(crate) async fn drain_steer(...)` pushes each pending steer as `ChatMessage::new(Role::User, text)`; called at the top of run_agent_loop (after clear_approval, before enforce_budget) and of run_delegate_subagent (delegate's dctx is a clone of the parent ctx so the bus propagates automatically via the delegate tool). 3. comrade-tui tui.rs: App fields steer_tx/queued_prompt/run_cancelled; start_run creates the bus and stores the sender; submit_prompt() = idle->start_run / running->steer(); steer() shows the user band then sends (falls back to start_run if the send fails, i.e. the run just ended); queue_prompt() appends to queued_prompt and shows the text + a meta note; RunEnd consumes queued_prompt (auto start_run unless cancelled -> restored into the Editor via insert). Keys: Enter -> submit_prompt, ctrl-Enter -> queue_prompt (idle: submit), shift-Enter still inserts a newline. New MxCommand variants QueuePrompt ('queue-prompt', C-<return>) and SteerPrompt ('steer', <return>); SubmitPrompt now routes through submit_prompt too. 4. headless untouched (steer stays None).

## Consequences
Steer delivery is at a loop REST POINT (top of each iteration, before the next model request), never mid-model-call, so ordering with assistant tool_calls/tool_results stays API-valid. The UI shows the steer/queued text itself (core does NOT emit AgentEvent::User for steers, to avoid duplicates). ToolContext gained a field, so every `ToolContext { .. }` literal needed `steer: None,` (mechanical; ~15 sites across comrade-tool/core/fs/session and both TUI files). Semantics verified by the user: ctrl-Enter queue delivers to the NEXT run when the current one ends; if the run was cancelled the queued text is restored to the prompt bar instead of auto-submitting. Steers sent when no run is live fall back to starting a new run. Verify: cargo test -p comrade-core -p comrade-tui (102 + 88) green.
