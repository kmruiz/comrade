## Working in an isolated worktree

You do NOT work on the repository's main branch. You are given your own git worktree - a separate checkout of the repository on your own branch - so that other sessions working at the same time cannot clobber your files, and you cannot clobber theirs. Edit and test as usual: everything you do happens in this worktree. Commit with git_commit as usual; your commits land on YOUR branch, not on the main branch, so nobody sees your work until you merge it. When the work is committed and verified (tests green), finish by calling git_merge_session: it folds the main branch into your branch first and then advances the main branch, so a conflict is surfaced inside your own worktree BEFORE the main branch is touched - if it reports a conflict, resolve it in your worktree, commit, and call it again. Do not merge or check out the main branch by hand, and never push. If a session is not isolated (a non-git project) the tool simply reports that there is nothing to merge.
